# Конспект по фронтенду проекта Flowers

## 1. Общая идея фронтенда

Фронтенд находится в папке `front` и представляет собой React-приложение интернет-магазина цветов. В нем есть две основные части:

- публичная часть магазина для пользователя;
- административная панель по адресу `/admin`.

Публичная часть позволяет смотреть главную страницу, открывать каталог, фильтровать товары, добавлять букеты в корзину, регистрироваться, входить в аккаунт, оформлять заказ и смотреть историю заказов. Также на сайте есть AI-ассистент по подбору букетов.

Административная часть позволяет администратору входить в отдельную панель, смотреть метрики, управлять заказами, товарами, пользователями, аудитом и прогнозом спроса.

## 2. Используемые технологии

По `front/package.json` видно, что проект собран на следующем стеке:

- React 19.2.0;
- React DOM 19.2.0;
- React Router DOM 7.13.2;
- Vite 8 beta как сборщик и dev-сервер;
- ESLint для проверки кода.

Основные npm-скрипты:

- `npm run dev` - запуск проекта в режиме разработки через Vite;
- `npm run build` - сборка production-версии;
- `npm run lint` - проверка кода ESLint;
- `npm run preview` - предпросмотр production-сборки.

## 3. Точка входа и маршрутизация

Главная точка входа - `src/main.jsx`.

В этом файле React-приложение монтируется в DOM-элемент `root`. Также там подключается `BrowserRouter`, поэтому приложение может использовать маршрутизацию из `react-router-dom`.

Дальше управление переходит в `src/App.jsx`.

В `App.jsx` настроены основные маршруты:

- `/` - публичное приложение `PublicApp`;
- `/admin/*` - административное приложение `AdminApp`;
- любой неизвестный путь перенаправляется на `/`.

Также в `App.jsx` есть небольшой защитный `useEffect`, который удаляет со страницы посторонний элемент `#tr-popup`, если он появляется в DOM. Для этого используется `MutationObserver`.

## 4. Публичная часть приложения

Главная логика публичной части находится в `src/PublicApp.jsx`.

Важно: внутри публичной части страницы переключаются не через URL, а через React-состояние `currentPage`. Возможные экраны:

- `home` - главная страница;
- `catalog` - каталог;
- `cart` - корзина;
- `auth` - вход и регистрация;
- `account` - личный кабинет;
- `checkout` - оформление заказа.

Главный компонент хранит состояние:

- `products` - список товаров;
- `cartItems` - корзина пользователя;
- `authUser` - текущий пользователь;
- `orders` - заказы пользователя;
- `accessToken` - токен авторизации;
- `catalogError`, `pageError` - ошибки загрузки и действий;
- `isCatalogLoading`, `isAppReady` - состояния загрузки.

При запуске публичная часть:

1. Загружает каталог через `fetchFlowers()`.
2. Проверяет, есть ли сохраненная сессия в `localStorage`.
3. Если токен есть, запрашивает текущего пользователя, корзину и заказы.
4. Если токен невалидный, очищает локальную сессию.

## 5. Компоненты публичной части

Основные компоненты лежат в `src/components`.

### Header

Файл: `src/components/Header.jsx`.

Это шапка сайта. В ней есть:

- логотип;
- навигация по главной, каталогу и корзине;
- бургер-меню для мобильного вида;
- кнопка профиля, которая открывает либо личный кабинет, либо страницу авторизации.

### Heros

Файл: `src/components/Heros.jsx`.

Это первый экран главной страницы, визуальный hero-блок сайта.

### Popular

Файл: `src/components/Popular.jsx`.

Компонент показывает первые 6 товаров из загруженного каталога как популярные букеты. У каждого товара есть изображение, название, описание, цена и кнопка покупки. Кнопка "Показать все" переводит пользователя в каталог.

### CatalogPage

Файл: `src/components/CatalogPage.jsx`.

Каталог реализует:

- вывод товаров карточками;
- фильтр по категориям;
- поиск по названию;
- постепенную подгрузку товаров кнопкой "Смотреть еще";
- состояния загрузки, ошибки и пустого результата.

Фильтрация сделана через `useMemo`, чтобы список пересчитывался только при изменении товаров, категории или поисковой строки.

### CartPage

Файл: `src/components/CartPage.jsx`.

Корзина считает:

- общее количество товаров;
- итоговую сумму;
- правильное русское склонение слова "товар".

Пользователь может:

- увеличить количество товара;
- уменьшить количество товара;
- удалить товар;
- продолжить покупки;
- перейти к оформлению заказа.

### CheckoutPage

Файл: `src/components/CheckoutPage.jsx`.

Страница оформления заказа содержит:

- поле адреса доставки;
- выбор способа оплаты;
- список товаров заказа;
- итоговую сумму;
- валидацию адреса перед отправкой.

После подтверждения данные уходят в `onSubmitOrder`, а сама отправка заказа выполняется в `PublicApp.jsx` через API.

### AuthPage

Файл: `src/components/AuthPage.jsx`.

Компонент объединяет регистрацию и вход. Переключение между режимами идет через состояние `mode`.

При регистрации фронтенд:

1. Проверяет, что логин и пароль заполнены.
2. Отправляет запрос регистрации.
3. Сразу выполняет вход.
4. Запрашивает текущего пользователя.
5. Сохраняет пользователя и токен в `localStorage`.

При входе выполняется похожий сценарий: логин, получение токена, загрузка текущего пользователя, сохранение сессии.

### AccountPage

Файл: `src/components/AccountPage.jsx`.

Личный кабинет имеет вкладки:

- профиль;
- заказы.

В профиле отображаются имя пользователя, роль, количество товаров в корзине и сумма корзины. Во вкладке заказов показываются оформленные заказы, статус, адрес, способ оплаты, состав заказа и дата.

### FlowerAssistant

Файл: `src/components/FlowerAssistant.jsx`.

Это чат-ассистент для подбора букетов. Он поддерживает:

- открытие и закрытие панели;
- быстрые промпты;
- отправку сообщения пользователя;
- потоковый ответ через SSE;
- fallback на обычный API-запрос, если streaming не сработал;
- рекомендации товаров;
- добавление рекомендованного товара в корзину;
- переход в каталог.

Для потокового ответа используется функция `streamFlowerAssistant()`, а запасной вариант - `askFlowerAssistant()`.

## 6. Работа с API в публичной части

Публичные API-функции находятся в `src/api/publicApi.js`.

Базовый адрес API берется из переменной окружения `VITE_API_URL`. Если она не задана, используется `http://127.0.0.1:8100`.

Основные функции:

- `registerUser()` - регистрация;
- `loginUser()` - вход;
- `fetchCurrentUser()` - текущий пользователь;
- `fetchFlowers()` - загрузка каталога;
- `fetchCart()` - загрузка корзины;
- `addCartItem()` - добавление товара в корзину;
- `updateCartItem()` - изменение количества;
- `deleteCartItem()` - удаление товара из корзины;
- `fetchOrders()` - заказы пользователя;
- `createOrder()` - оформление заказа из корзины;
- `askFlowerAssistant()` - обычный запрос к AI-ассистенту;
- `streamFlowerAssistant()` - потоковый запрос к AI-ассистенту.

В этом же файле есть нормализация данных:

- `normalizeFlower()` приводит товар с backend-формата к frontend-формату;
- `normalizeOrder()` приводит заказ к удобному формату для отображения;
- `normalizeCartItem()` готовит элементы корзины.

Это удобно, потому что компоненты работают с единым форматом данных и не зависят напрямую от структуры ответа сервера.

## 7. Авторизация пользователя

Файл: `src/utils/authStorage.js`.

Сессия пользователя хранится в `localStorage`:

- `flowersSessionUser` - данные пользователя;
- `flowersAccessToken` - access token.

Функции:

- `saveSession()` - сохранить пользователя и токен;
- `getSessionUser()` - получить пользователя;
- `getAccessToken()` - получить токен;
- `logoutLocalUser()` - очистить сессию.

Если API возвращает ошибку `401`, публичная часть очищает сессию и переводит пользователя на страницу входа.

## 8. Корзина и optimistic update

При добавлении товара в корзину в `PublicApp.jsx` используется optimistic update.

Это значит, что интерфейс сразу показывает товар в корзине, не дожидаясь ответа сервера. Если сервер отвечает успешно, временный элемент заменяется реальным элементом из API. Если запрос завершается ошибкой, корзина откатывается к предыдущему состоянию.

За это отвечают:

- `buildOptimisticCartItem()`;
- `addToCart()`;
- сохранение `previousCartItems` перед запросом;
- откат `setCartItems(previousCartItems)` при ошибке.

Такой подход делает интерфейс быстрее и приятнее для пользователя.

## 9. Административная панель

Админка находится в `src/admin`.

Главный файл - `src/admin/AdminApp.jsx`.

Маршруты админки:

- `/admin/login` - вход администратора;
- `/admin/dashboard` - сводка;
- `/admin/orders` - заказы;
- `/admin/products` - товары;
- `/admin/forecast` - прогноз спроса;
- `/admin/users` - пользователи;
- `/admin/audit` - журнал действий.

Защита маршрутов сделана компонентом `RequireAdmin`.

## 10. Защита админки

Файл: `src/admin/components/RequireAdmin.jsx`.

Компонент проверяет:

1. Есть ли admin token в `localStorage`.
2. Валиден ли токен через запрос `adminMe()`.
3. Имеет ли пользователь роль `admin`.

Если токена нет или проверка не прошла, пользователь перенаправляется на `/admin/login`. Если пользователь не админ, показывается сообщение `Access denied`.

Admin token хранится отдельно от пользовательского токена в `src/admin/auth/adminAuthStorage.js` под ключом `flowersAdminToken`.

## 11. Layout админки

Файл: `src/admin/components/AdminLayout.jsx`.

Админка имеет общий layout:

- боковое меню;
- название раздела;
- кнопка выхода;
- кнопка возврата на сайт;
- область, куда через `Outlet` подставляется текущая страница.

Навигация сделана через `NavLink`, поэтому активный пункт меню подсвечивается автоматически.

## 12. Страницы админки

### AdminLoginPage

Файл: `src/admin/pages/AdminLoginPage.jsx`.

Страница входа администратора. По умолчанию в форме стоят демо-данные `admin/admin`. После входа фронтенд сохраняет admin token, проверяет роль через `adminMe()` и переводит в dashboard.

### AdminDashboardPage

Файл: `src/admin/pages/AdminDashboardPage.jsx`.

Панель считает метрики на основе списка заказов:

- общую выручку;
- количество заказов;
- средний чек;
- количество заказов по статусам.

Метрики считаются на фронтенде из ответа `/admin/orders`.

### AdminOrdersPage

Файл: `src/admin/pages/AdminOrdersPage.jsx`.

Раздел управления заказами:

- загрузка всех заказов;
- фильтр по статусу;
- просмотр состава заказа;
- пересчет суммы заказа;
- изменение статуса;
- удаление одного заказа;
- удаление всех заказов.

Перед удалением используется `window.confirm`.

### AdminProductsPage

Файл: `src/admin/pages/AdminProductsPage.jsx`.

Раздел управления товарами:

- загрузка всех товаров;
- создание нового товара;
- редактирование существующего товара;
- удаление товара;
- удаление всех товаров;
- валидация обязательных полей перед сохранением.

Форма одна и для создания, и для редактирования. Если выбран `editingId`, форма работает в режиме редактирования.

### AdminUsersPage

Файл: `src/admin/pages/AdminUsersPage.jsx`.

Раздел пользователей:

- просмотр всех пользователей;
- отображение роли;
- дата создания;
- удаление пользователя;
- массовое удаление пользователей, кроме текущего администратора;
- запрет удаления admin-пользователя через disabled-кнопку.

### AdminAuditPage

Файл: `src/admin/pages/AdminAuditPage.jsx`.

Журнал аудита показывает действия администратора:

- дата;
- actor username;
- action;
- entity;
- entity id.

При выборе события справа отображаются данные `before` и `after` в JSON-формате.

### AdminForecastPage

Файл: `src/admin/pages/AdminForecastPage.jsx`.

Страница прогноза спроса. Она работает с endpoint-ами прогноза и показывает:

- статус модели;
- горизонт прогноза;
- страховой запас;
- метрики модели: MAE, RMSE, MAPE, Accuracy;
- таблицу прогноза по датам;
- план закупки;
- кнопку переобучения модели.

Параметры `days`, `testDays` и `safetyStock` хранятся в состоянии компонента.

## 13. API админки

Файл: `src/admin/api/adminApi.js`.

Базовый адрес API также берется из `VITE_API_URL` или по умолчанию `http://127.0.0.1:8100`.

Функция `adminFetch()` автоматически:

- добавляет `Authorization: Bearer ...`;
- читает JSON-ответ;
- обрабатывает ошибки;
- очищает admin token при `401`.

Основные группы API:

- авторизация: `adminLogin()`, `adminMe()`;
- заказы: `adminListOrders()`, `adminUpdateOrderStatus()`, `adminDeleteOrder()`, `adminDeleteAllOrders()`;
- пользователи: `adminListUsers()`, `adminDeleteUser()`, `adminDeleteAllUsers()`;
- товары: `adminListProducts()`, `adminCreateProduct()`, `adminUpdateProduct()`, `adminDeleteProduct()`, `adminDeleteAllProducts()`;
- аудит: `adminListAudit()`;
- прогноз: `adminForecastHealth()`, `adminForecastMetrics()`, `adminForecastList()`, `adminForecastRetrain()`.

## 14. Стили и визуальная часть

Стили разбиты по компонентам:

- `App.css`, `main.css` - базовые стили приложения;
- `components/*.css` - стили отдельных публичных компонентов;
- `admin/admin.css` - стили всей админ-панели.

Также в проекте подключены локальные шрифты из `src/fonts` и изображения из `src/assets` и `public/images`.

## 16. Короткая формулировка для защиты

"Я реализовал фронтенд интернет-магазина цветов на React и Vite. Приложение разделено на публичную пользовательскую часть и административную панель. В публичной части есть каталог с фильтрацией и поиском, корзина, авторизация, личный кабинет, оформление заказов и AI-ассистент для подбора букетов. Все запросы к серверу вынесены в отдельный API-слой, а данные нормализуются перед передачей в компоненты. Пользовательская сессия хранится в localStorage, при ошибке авторизации автоматически очищается. Админка вынесена в отдельный маршрут `/admin`, защищена проверкой токена и роли администратора, и содержит страницы для управления заказами, товарами, пользователями, аудитом и прогнозом спроса."
